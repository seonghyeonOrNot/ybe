# y-BE 관리자 디자인 시스템

y-BE 관리자 화면 8개 페이지(휴가 대상자 관리, 근태현황, 조직·구성원 관리, 전자계약 현황, 연차 설정, 휴가 형태 관리, 게시판 관리, 컬러테마 설정)를 실제로 열어 computed style을 뽑아 역설계한 디자인 시스템입니다. Figma나 별도 컴포넌트 라이브러리 없이, **운영 중인 화면 자체가 소스입니다.**

## 사용자(Staff) 스킬과의 관계

버튼·탭·모달의 shape/spacing/타이포 규칙은 ybe-staff-design-system과 공유됩니다. 색상만 다릅니다(이쪽은 네이비/블루, staff는 틸). 이 스킬의 Foundation 값을 바꿀 경우 반드시 ybe-staff-design-system도 함께 갱신할 것.

## 사용 원칙

1. **새 이름을 짓지 말 것.** y-BE는 이미 .btn.point, .btn.positive, badge1-1, .txt-notice.info 같은 클래스 체계를 갖고 있습니다. 이 스킬은 그 기존 이름을 그대로 기준으로 삼습니다. color-primary-900 같은 새 토큰 이름을 만들지 마세요 — 문서와 실제 코드가 어긋납니다.
2. **컬러는 변수 취급.** 컬러테마 설정 페이지에서 회사가 브랜드 컬러를 5종(기본 #5F9CF8 외 4종) 중 선택할 수 있게 되어 있습니다. 즉 이 서비스는 이미 테마 토큰화를 전제로 설계돼 있습니다. 지금 문서화된 네이비 계열은 "현재 적용된 테마 값"이지 하드코딩해도 되는 고정값이 아닙니다. 화면을 만들 때 이 값을 쓰되, 나중에 테마가 바뀔 수 있다는 전제를 유지하세요.
3. **관리자 화면 전용.** 이 스킬의 모든 값은 Admin 화면에서 뽑은 것입니다. 사용자(직원) 화면 — 전자결재, 휴가 선택 모달 등 — 은 별도로 검증되지 않았으므로 이 토큰을 그대로 적용하지 말고, 사용자 화면 작업 시에는 먼저 실측을 요청하세요.
4. **패턴이 있으면 규칙으로, 없으면 지어내지 말 것.** 아래 Foundation/Component 섹션에 없는 값(예: 특정 컴포넌트의 hover 상태, 반응형 브레이크포인트)은 추측하지 말고, 기존 규칙에서 가장 가까운 패턴을 유추해 적용하거나 사용자에게 확인을 요청하세요.

## Foundation

상세 토큰 표(전체 hex 값, 타입 스케일, radius/shadow 스펙)는 references/foundation-tokens.md 참고. 핵심 요약:

- **컬러**: 네이비 3단(#1B164D 사이드바 > #2A2873 테이블헤더 > #312E98 주요버튼/필터라벨) + 블루 2단(#3371FF 액션, #2285F1 강조탭) + 상태색(안내 시안 #009DDF, 경고 핑크 #F957C6) + 배경(#EFF1F7 콘텐츠 영역, 흰색 카드/테이블)
- **타이포**: Montserrat + Gmarket Sans, 6단 스케일(Display 30px/800 → Section Title 20px/800 → Title 19px/700 → Body-lg 16px/600 → Body 14px/600 → Caption 13px/600). 전체적으로 weight가 600~800에 몰려있어 기본 400을 쓰면 톤이 어긋남.
- **Radius 규칙**: "필터/입력 요소는 pill(100px+), 데이터/콘텐츠 영역은 sharp(0)"이 일관된 규칙. 필터 라벨-필드 결합형은 비대칭 radius(30px 10px 33px 30px).
- **Shadow**: 일반 플로팅(드롭다운) vs 이 서비스 고유의 "Stepped Shadow Header"(연차설정/컬러테마 설정 페이지의 섹션 헤더, 7단 계단식 #8FBFF9 그림자) 두 종류.

## Components

상세 variant/state 표는 references/component-patterns.md 참고. 핵심 요약:

- **Button**: .btn 베이스 + 색상 클래스로 분기 — Primary(point, #312E98), Secondary(#3371FF), Dark(#12114E, 강조 보조액션), 각각 Outline 버전 존재. 세그먼트 토글 패턴(두 버튼 붙여서 바깥쪽만 radius) 있음.
- **Tab**: 3종 — Rounded(상단 콘텐츠 탭, 활성시 #2285F1 채움+상단만 16px 라운드), Toggle(게시판 관리, 사각 pill, 활성 #312E98), Stepped(연차설정, 세로형 스텝섀도우). 통일하지 말고 페이지 성격에 맞게 3-variant 그대로 유지.
- **Form**: pill 인풋(126px, 테두리 #CCC), 원형 커스텀 라디오/체크박스(선택시 네이비 dot), 날짜/숫자 입력, 라벨-필드 결합형(활성 네이비/잠금 #9EADCC)
- **Data display**: 다크 네이비 헤더 테이블(5개 페이지 재사용), 통계 카드(#F1F4FF bg, 숫자 29.6px/700), jsTree 조직도, 게시판 고정글 하이라이트, 원형 페이지네이션(32px, 현재페이지 #8D9DC4)
- **Modal**: modal.mid 클래스 — 1200px 폭, 배경 #FEFEFE, radius 26px. 등록/수정/변경이력/사용이력 모달 전부 이 구조 재사용.
- **Floating/Notice**: 드롭다운 카드(radius 10px + 플로팅 섀도우), Notice Banner(체크아이콘 불릿 리스트, 4개 페이지 재사용되는 공통 컴포넌트)

## 알려진 리스크 / 미검증 항목

- prototype/leave-usage-history.html 파일 안의 블루 계열(#4361ee) 팔레트는 **오래된 초안일 가능성이 높음** — 실제 운영 화면(이 스킬의 네이비 계열)과 다름. 이 파일의 마크업 구조(뱃지/테이블 클래스)는 참고하되 색상값은 이 스킬의 Foundation 값을 우선 적용할 것.
- 사용자(직원) 화면, 특히 전자결재 > 휴가 선택 모달은 아직 실측되지 않음. 별도 스킬 또는 이 스킬의 향후 업데이트로 추가 예정.
- Hover/disabled 등 인터랙션 상태값, spacing/그리드 토큰은 부분적으로만 확인됨. 정밀한 픽셀 단위 구현이 필요한 작업이면 추가 실측을 먼저 요청할 것.
